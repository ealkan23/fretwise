# Fretwise

Guitar music-theory, ear-training, rhythm and microphone trainer for an aspiring jazz guitarist (Berklee-style curriculum). Single-page app, no build step for development, no framework. One vendored dependency (user-approved): Spotify Basic Pitch + TensorFlow.js in `vendor/` for guitar note detection.

- **Live site (the one page the user uses):** https://ealkan23.github.io/fretwise/ — GitHub Pages from the public repo `ealkan23/fretwise`. `.github/workflows/pages.yml` publishes `src/fretwise.html` as `index.html` with `piano/` beside it on every push to `main`, so **deploying = commit + `git push`** (watch with `gh run watch`). Mic works there; progress is in that browser's `localStorage` key `fretwise-v1`. The user works only from Claude Code: never send them to a claude.ai chat to publish.
- **Old claude.ai artifact (retired):** https://claude.ai/artifact/756Z4Kc3AywDU1mgsGazsQ — no longer updated. `initCloud` only runs when framed with `window.claude`; elsewhere it shows "Saved in this browser". Progress moves between copies with Overview → "Move your progress" (export/import JSON; per game the copy with more answers wins).
- **Offline file:** `dist/fretwise.html` (built by `build.py`, piano embedded, git-ignored). Open from disk in Chrome.
- **Pedagogical review** that drove the roadmap: https://claude.ai/artifact/7emdzZtQ8s6Eb2FDthZEUL

## The full notes, made simpler (17 Nov 2026, the same day; user: “very complicated… Scale Runner can be explained in way simpler terms… don't repeat the same things in different games… some are good, don't force changes… without omitting important information”)
An editing pass over all 39 games (nine editors, one brief): about 162,600 → 139,500 words, 474 chapters, 590 figures, 313 tables. **The rules the notes now follow, and that any new note must follow:**
- **The plain idea first**, in ordinary words; one idea at a time in the order a learner needs it; the complete system (all twelve fingering types, every case) comes last as a look-up reference. A figure is not re-described in prose. How the grader measures is said only as the rule the player must follow.
- **One home game per shared topic**; other games keep the two or three sentences they cannot do without and may point to the home by its display name. Homes: the neck's layout, the G–B shift, octave shapes → Fretboard · the staff, ledger lines, reading positions → Reading · half and whole steps, interval names, the major scale, key signatures, the circle of fifths, the minor scales → Intervals & Keys · chord formulas → Chord Spelling · diatonic harmony, function, secondary dominants, substitutes, modal interchange → Harmony & Analysis · positions and Leavitt's fingering types → Scale Runner · the modes → Modes (practical: one chord, its scales, the colour note) and Chord–Scale Reflex (the reasoning and the full table; assumes Modes) · pentatonic and the five boxes → Blues Boxes · guide tones through II–V–I → Guide-Tone Voice Leading · pulse, subdivision, counting, 2 and 4, swing eighths → Pulse & Feel · written figures and their counts → Reading Rhythm (Rhythm Theory keeps meter, beaming, signs, dictation) · the Charleston and pushes → Jazz Rhythm (Comping keeps the hands and the chords) · hearing the key → Hear the Degree · the blues forms and song forms → Repertoire · hear, hold and play back a phrase → Tunes by Ear · general practice advice → nowhere as a chapter.
- Scale Runner was reworked most (the user's example): it opens with what a position is and one shape (C major in position VII), then stretches, then the game's order; the twelve types are the last chapter.
- Each editor reported what it cut that “might be missed” (per-key tables, some second figures); the originals of this pass are not kept in the repo, the version before it is commit `The full notes rewritten as textbook chapters` (git history).
- One more game fault reported and still open: Comping's swing levels seem to grade the off-beat at the straight eighth (`COMP` onsets at .5; `cComp` does not apply the 0.67 shift).

## Speed shown in real seconds on mixed levels (17 Nov 2026, user: “Intervals & Keys level 1's speed metric is so low for no reason”)
`g.ht[L]` holds ratios (time ÷ the question's own target). Every display multiplied the median ratio by the level's median target (`lvTargetSec`); on a level whose questions have very different targets (Intervals & Keys 1: one note 2.5 s, which degree 7.7 s, a whole scale 8.5 s) that showed 19 s for answers that take about 7. Now: `g.hs[L]` stores the same clean answers in seconds (from now on; `migrateReorder` remaps it), `lvMixed(gid,L)` = targets differ by more than 1.5×, and `lvTargetEff(gid,L)` (used by the lobby row, the stats page, the masters' facts) = real seconds ÷ ratio on mixed levels (until `hs` has three answers: the level's average answer time), else `lvTargetSec`. The unlock rule itself (median ratio ≤ 1) is unchanged. On the user's data Intervals & Keys 1 reads 7.2 s against 2.9 s (was 19.0 against 7.7). **Open question put to the user**: the one-note target (1.5 s + 1 s = 2.5 s) against their 6.5 s average, and “which degree” on a number key having the looser 7.7 s choice target.

## The full notes are textbook chapters (17 Nov 2026, user: “full-fledged textbook information… chord shapes, infographics, the clef and musical notation… never fluff, don't reduce”; snapshot before it: commit df… `Reading Rhythm: quarter-note and half-note triplets`)
- **A page of its own**: the lesson card's button “Open the full notes” → view `notes` (`vNotes`, `notesBody` cached in `NOTES_HTML`, actions `notes`/`notesec`): the master's name, a chapter list, the chapters. The collapsed `<details>` inside the lesson card is gone.
- **Content**: `LESSON_NOTES.<id>=[{h,p:[…]}]`, one statement per game in the block “THE FULL NOTES” just before the VIEWS marker (some are IIFEs with helpers; many table rows are computed when the script loads, so the block must stay after the music core and the generators). 39 games, about 160,000 words, 665 figures, 377 tables; the script went from 1.3 to 2.2 MB. The `const LESSON_NOTES={…}` literal holds only the retired Guide Tones' old notes. An item of a chapter: a string (paragraph), an array (bullets), `{sub}`, `{fig:()=>html,cap}`, `{tbl:[head,rows],cap}`, `{tip}` (“From the player's chair”); `noteItem` renders one, `noteText` gives plain text (the masters' chat prompt carries the notes).
- **The figure kit `NF`** (before `const LESSON_NOTES`): `grip(title,tab,root,labels)` / `grips` (chord box with the interval in every dot; **labels are verified against the sounding notes**), `neck('6/8=C* 5/7=E!')`, `neckSVG(dots)`, `scale(root,formula,lo,hi,{names,hl,strings})`, `where(notes,lo,hi)`, `staff('C4=1 E4 | C4+E4+G4',{ks})` (treble staff as written for guitar, key signature, naturals), `rhy('q ee | trip q h',{meter,ts})` (from `RCELL`; a bar must fill its meter), `circle({key}|{minor})` (three rings: major, relative minor, diminished, the count of sharps or flats; the seven chords of a key picked out with numerals), `table`, `row`. Faults go to `NF.err`; the sweep fails on any, and `tests/pages_check.py` renders every notes page.
- **How it was written**: nine agents, one per group of games, from one brief (complete coverage of the subject, shapes from the app's own generators, the user's conventions, no copyrighted melodies, nothing attributed to a book unless already in the notes), each draft checked (≥8 chapters, ≥1,800 words, ≥8 figures or tables, 5 for ear games, ≥3 tips, no em dashes, Berklee numerals) and looked at as rendered pages. I looked at eight chapters across eight games after the merge; **the text has not been proof-read line by line by me or by the user's teacher**.
- **When levels are added or changed, the game's chapters need the same change** (they describe what the levels ask). To edit a chapter, edit its statement in the block; keep it one statement per game.
- **Faults in the games that the writers reported and that are still open** (not fixed here): Arpeggio Runner level 5 `bebopRun` starts a fourth above the named root and shows wrong note names · `rhySVG` splits a dotted half in 3/4 from the second bar on (`t%4`) and never draws eighth–quarter–eighth with a quarter · `CH['13']` holds the 11 (Hear the Chord level 6) · `shellCycleQ` from string 5 falls back to a II–V–I question about half the time · `gtVLQ` IMaj7 → VI7 accepts only the upward move · Hear the Mode level 7's prompt names the mode · the descending passing diminished chord is spelled ♯II°7 · `COMP.bossa.d` says “and 3” for beat 4 · stale texts: `LESSONS.scales.how` (“not from the root”), `LESSONS.sing.how` and Sing It's area (“solfège”), `IVREF` and `LESSONS.eariv` (song mnemonics), `GAMES` descriptions of arp, triads, cr, comping, jazzrhy; several `LEVEL_NOTES` (analysis 8, fretboard 13, sight 17, cr 1, jazzrhy 2, comping 7, scales 2) · `FORMS` note for All The Things You Are says C is a major third below A♭.

## Groove: the continuous format (user design, 6 Nov 2026)
The four kinetic rhythm games (Pulse & Feel, Reading Rhythm, Jazz Rhythm, Comping) no longer use rounds. `start(gid,L)` routes any level with a `c` spec to `grooveStart`: one session, the click never stops (`GR.beats` grid for `GRV.max` = 180 s, per-beat tempo so `bpm2` can alternate tempos), expected hits generated 8 bars ahead from `c.bar(k,M)` (`grooveBars`), taps (`grooveHit`, latency-corrected) or mic onsets (`LS.ons` polled live) matched to the nearest expected hit within `tapTol` (`grooveMatch`; unmatched = extra, which breaks the hold). Dashboard: moving averages over the last 16 and 64 resolved hits (tightness = mean |offset|, lean = mean offset, misses), a sliding timeline canvas (`grooveDraw`), and the hold bar: `GRV.hold` (64) consecutive hits within the game's `STD.ab` (feel levels also need the 16-hit lean within ±15 ms of `c.feel(bar)`) unlock the level (`g.lvl++` in `grooveRecord`). Every 8 resolved hits write one entry to `g.hist[L]`/`g.hm`/`g.lc`/`g.pl` (an entry is 1 when all 8 were hit within tolerance with no extra hit: accuracy means hit rate; the 25 ms standard is judged by the timing numbers and the hold bar, not by accuracy — the first version scored blocks by the standard and showed 0% at 240/240 hits, wiped by `mig.gh1`); a keyboard-made click on the TAP button (`e.detail===0`) is ignored, Space already counted it; **The hold and the unlock** (6 Nov 2026 evening, user: 240/240 hits, tightness 24 ms, best hold 9 — “why can't I open the next level?”): the hold counts hits in a row without a miss or an extra hit (`GR.hold`, breaks on those only); the level unlocks when `grooveMeets()` holds: hold ≥ `GRV.hold` **and the tightness over the run ≤ `STD.ab` and over its last 16 hits too** (`end`: tight at the end, not coasting). **The hold is counted in clean bars since 9 Nov 2026** (user: Reading L1 has one or two attacks a bar, so 96 hits took ~50–90 bars): `GRV.hold` = 24 bars; a bar is clean when every written hit landed within tolerance, nothing extra fell in it and every length was right (`grooveLoop` completes bar k once its end + tol has passed; `grooveBreak(fromBar)` resets the run and `GR.holdFrom` on a miss, extra or length fault); `grooveMeets` measures tightness over the hits inside the run (`o.bar ≥ GR.holdFrom`) and needs at least `GRV.minHits` (16) of them; fire from 2 bars, full at 24, bursts every 4. (History: 64 hits → 96 hits → 24 bars.) (the moving average the user asked for; a per-hit bound equal to the average standard made a run of 64 statistically impossible — the first version did that). ## Latency (6 Nov 2026): reported, never learned
Taps in the continuous games are corrected only by the audio device's reported output latency (`outLat()` = `AudioContext.outputLatency + baseLatency`, read when the click starts: the browser reports a smaller number before audio runs). Nothing is learned from the player's taps any more (`tapLearnLatency` is no longer called; it was circular and would erase a real lean). `opts.raw` applies no correction; the lobby shows the reported value and warns above 80 ms (Bluetooth). The mic path corrects onsets by `micLat(false)` = reported output latency + 40 ms (an estimate of capture + onset detection), re-read at every onset (the one-time read at `startListening` caught the pre-audio 6 ms figure in continuous sessions), so groove applies `GR.lat` to taps only. The 40 ms could be measured with a speaker→mic loopback on the Mic check page (not built). Measured 6 Nov 2026 on the user's Mac (built-in device, 44.1 kHz): baseLatency 5.8 ms, outputLatency 32 ms, `currentTime` steps of 2.9 ms, `getOutputTimestamp` agrees with the reported figure to 2 ms. The player's constant lean is therefore not a latency error; see the groove section (steadiness around the centre). The user had switched `opts.raw` on; leave it to them. Scheduled ticks are tracked in `TICKS`; `Piano.tickStop()` silences the ones still to come (`grooveEnd`, `tapAbort`): the click no longer runs on after a session ends.

## Architecture (all in one script, top to bottom)

1. **Music core** — `P()` parse note name → `{l,a}` (letter index, accidental), `pc`, `nm`, `tr(root,num,semi)` spell an interval up, `trDown`, `IV` interval table, `CH` chord formulas, `chord()`, `scale()`, `SC`, `diatonic`, `respell`, `mc(ans,distractors,n)` builds a shuffled choice list, `C()`/`A()` question wrappers (choices / audio), `okAcc` (limit double accidentals), `rootPick(list)` (twelve-key coverage: prefers roots this game has seen least; sets `LAST_ROOT` which pickQ stores as `q.rootKey`).
2. **Drawing** — `fretSVG({dots,click,win})` (string 1 on top, dots `{s,f,cls,t}`), `staffSVG` (accidentals drawn as paths, not glyphs), `boxSVG` chord diagram, `rhySVG` rhythm notation, `tapTimeline`, `circleSVG`.
3. **Piano** — `Piano` sampler: `load/note(midi,t,dur,vel)/chord/tick/ready/now`; source is `window.PIANO_DATA[name]` when present (dist) else `piano/<name>.mp3`.
4. **Sound engine** — `playSnd(q,g)` plays a question's `snd` descriptor after answering (`note | seq | scale | chord | grip | prog | chordseq`); every generator attaches one. Ear games use `q.audio()` instead (returns duration in seconds; timer starts after it).
5. **Mic** — guitar games (everything but Sing It and Comping) use **Basic Pitch** (`BP`, `bpLoad`, `bpAnalyse`, `bpMono`, settings `BPO` tuned on the recordings): audio captured on the audio thread (`BP_CAP` AudioWorklet, loaded from a data: URL because blob: fails on file://; capturing on the main thread drops chunks while the model runs and the gaps read as new picks), the last 6 s re-analysed every 0.4 s, the whole take once more on stop. Falls back to the built-in detector without WebGL. Built-in detector: YIN pitch (`yinPitch`), `segment()` (attack + pitch-change segmentation, octave-shadow filter, `mf` float midi for cents), `startListening(onDone,maxNotes,{beat,beatStart,limit,onsets})` (onsets mode records attacks only, for strummed comping), `micGrade` (strict/octave-free, held-note merging, swing `grid`, alternative `targets`), `micPanel/slotsTarget/slotsHeard`, tuner view.
6. **Tap engine** — `tapBegin/tapHit/tapGrade` against an audio-clock-scheduled click; latency learned per game from clean rounds (`g.opts.lat`).
7. **Generators** — one closure per question type, returning a question object (schema below). Grouped by game; the drop-2 sheet `D2C`/`D2PROG`/`COMBO` is the user's own voicing sheet, keep its grips as they are. `genDrop2`, `drop3Grips`, `shellGrip`, `triadGrips`, `spreadGrips` generate grips and verify them against chord tones.
8. **Play mode** — `toPlay(q)` converts a `multi`/`fret` question into a strict `mic` question (exact pitches, ascending, alternatives preserved) when `g.mode==='play'`; `PLAY_GAMES` lists the games that offer it.
9. **GAMES / CATS** — each game `{id,cat,name,area,desc,levels:[{n,d,g:[generators]}], mic?, tap?}`; level count varies (5–16). **Level numbers index saved histories**: append new levels; any insert or reorder needs an entry in `REORDERS` (new flag if it is a second reorder of the same game) and a `PATH` update. Chord Spelling was rebuilt on 2 Nov 2026 (recall levels: majors by heart around the cycle of fourths, then alterations; `recallQ`, `altExplain`) and its saved data reset once at the user's request (`v2` in `G()`). A reorder needs a migration in `G()` (see `v7` for fretboard, `v67` for Note Hunt levels 6↔7, 2 Nov 2026). A level with `open:true` is playable before it is reached (Note Hunt L6 “Fret by fret”); review draws only from unlocked levels, stretch only from your own level.
10. **Store / sync** — `STORE.games[id]` = `blank()` fields (`lvl,last,limit,review,preview,round,sound,mode,opts,rk,sessions,items,cf,hist,best,n,c,ms,time,pn,pc`, plus `pl,sp` from the stats log); `K(key)` hashes item keys; `saveGame` → localStorage + artifact db; `initCloud` waits for the runtime, retries, surfaces errors (`CLOUD_MSG`), merge rule "more answers wins".
11. **Engine** — `pickQ` (review 25% / preview 15% mix, weakest-item weighting, `rare` generators), `start/nextQ/answer/finish/quit`, `check/givenText` per `ui`, level unlock at `NEED=16` recent answers ≥ `PASS=.85` clean.
12. **Stats analysis** — `perfLog` (in `answer`) records per answer: `it.r` last 8 results, `it.rt/rn` time to first played note, `it.gp/gn` note-to-note find time, `it.qn/qc` mic answers since the Basic Pitch detector, `g.pl` log (≤300) `{t,lv,k,ok,rt,gp,n,dr,ab}` (dr/ab = signed/abs offset to the click, ms), `g.sp` find time per slot label (strings in Note Hunt, chord tones in arpeggios). `coachNotes` writes the teacher's notes (prioritised, max 5), `focusItems` the practice list. Analysis skips pre-detector guitar mic results (`trusted`, `OLDMIC`), caps rounds left open (`roundCap`).
12a. **Statistics page (rebuilt 12 Nov 2026)** — `vStats` shows what each kind of game is about over the last 60 days. Daily history `g.days[YYYY-MM-DD]` = `{n,c,ms,dur,tn,dr,ab,gn,gp,rn,rt,hold}` (`dayAdd` from `answer`, `finish`, the groove blocks and `grooveEnd`; `dayPrune` keeps 60 days; `dayBackfill`, flag `d60`, rebuilt it once from the stored rounds and the performance log). Own panels: neck heat map (Fretboard, Reading), note table (Note Hunt), by key, `groupBars` by tune (Tunes), by fingering type and pattern (Scale Runner), by chord type (grip and spelling games), where you hesitate (`g.sp`). Then at most three coach notes, the practise-next list, repeated mistakes, and the level table (answers, recent accuracy and the level's measure from `lvMetrics`/`metricBits`, passed / at standard). Removed as uninformative: best streak, score, the recent-rounds table.

## Question object

```
key        stable id for stats (same item across modes); label  short text for stats tables
ui         'choices' | 'letters' | 'pc' | 'fret' | 'multi' | 'mic' | 'tap' | 'spell'
answer     choices: string · letters: 'F♯' · spell: ['D','F♯','A'] (need = count; entered note by note, S.spell) · pc: 0-11 · fret: validated by valid(s,f) · multi: [{s,f}] (+ alts: [[{s,f}]]) · mic: target midis · tap: onsets in beats
prompt, explain, hint, answerText, visual (html), reveal (html or {dots}), staff/staffOk, win [lo,hi], mark, fixedDots
factor     time multiplier (Infinity = untimed); rare: true = only when drawn first
snd        answer sound descriptor; audio() for ear questions (returns seconds)
mic:       target, targets (alts), names, degs, octaveFree, maxNotes, metro (bpm), grid (beat positions), hideTarget, after()
tap:       bpm, len (beats), countIn, clicks (beats in bar that click), onsets, call (onsets played first), mic (grade from onsets), dropOut
```

## Conventions the user has asked for

- Scale degrees as numbers; Roman numerals only in Berklee form (IIm7, V7, IMaj7 — always upper case, quality in the symbol).
- Drop-2 naming "from close" only (never "by bass note" in questions).
- Find-the-grip questions are mark-on-neck (or play it), never tab multiple choice.
- **Sound: no piano-only rule any more (16 Nov 2026, user: “It wasn't supposed to be a rule like this. Use whatever instrument serves the educational point”).** Any instrument or sound may be used where it teaches better (bass, drums, guitar samples). Older notes in this file that cite “the piano-only sound rule” as a blocker (Hear the Chord with guitar audio, drums only on the Metronome page) are superseded. Check the licence of any new samples before vendoring them.
- Keep all stats; never reset or restructure `STORE` without a migration (see the fretboard `v7` level-shift migration in `G()`).
